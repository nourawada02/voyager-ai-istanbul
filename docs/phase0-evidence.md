## Discovered SDK interface facts (used, not assumed)

- `a2a-sdk` 1.x's `Task`/`Artifact`/`Message`/`AgentCard` are
  **protobuf-generated** models (`a2a_pb2.*`), not Pydantic.
- `AgentCard` has no top-level `url`/`preferred_transport` field; the RPC
  URL(s) and transport binding(s) live in `AgentCard.supported_interfaces`
  (repeated `AgentInterface{url, protocol_binding, tenant,
  protocol_version}`).
- `MCPServer.tool()` registers directly on the server instance (no `.tools`
  sub-accessor); the v2 line's server class is `MCPServer`, not `FastMCP`.
- `MCPServer` mounts its Streamable HTTP route at `/mcp`.
- `A2ACardResolver.get_agent_card()` and `ClientSession.initialize()` are
  both `async`.
- On this machine, `subprocess.Popen([<venv>/Scripts/python.exe, ...]).pid`
  is a launcher-stub PID that differs from the real interpreter's
  `os.getpid()` (confirmed via an isolated repro unrelated to ADK/A2A/MCP).
  Each server now writes its true PID to a `--pid-file` at startup; the
  harness reads that file rather than trusting `Popen.pid` for the
  self-reported-PID-matches-launched-process assertion. `Popen.pid` is
  still recorded, labeled `*_launcher`, for transparency.

### Evidence corrections applied after an independent audit

An audit of the passing implementation found the harness's own evidence
was weaker than its claims in three respects, and one further dependency
gap (`starlette`, above). All three were corrected in code (not just in
this document) and re-verified live, as reflected in the result above:

1. **Actual application PIDs, not just launchers.** The harness previously
   only asserted the three *launcher* `Popen.pid` values were distinct —
   not equivalent to the three real running processes being distinct,
   given the launcher-vs-true-PID divergence noted below. `graph_client.py`
   already reported its own `os.getpid()`; the harness now reads it,
   asserts all three true PIDs (`planner`, `a2a_server`, `mcp_server`) are
   mutually distinct, and keeps launcher PIDs only as labeled diagnostic
   information (`pids.*_launcher`).
2. **Artifact validation, not message text.** `_call_a2a` previously pooled
   text from status messages, standalone messages, and artifacts together
   and accepted a nonce from whichever text happened to contain one first.
   It now requires `TASK_STATE_COMPLETED`, requires at least one official,
   `isinstance`-validated `Artifact` (also validating each `Part` within
   it), and extracts the nonce/pid/marker only from that validated
   artifact — a status or standalone message can no longer satisfy this.
   The harness additionally fails if `artifact_count` is missing or zero.
3. **Selected transport binding recorded, not assumed.** `requested_protocol_bindings`
   was previously always `[]` (an unset default) and no field recorded
   what the client actually used. The A2A node now explicitly requests the
   binding(s) the discovered Agent Card itself advertises
   (`supported_protocol_bindings=card_bindings`), and records the matching
   interface's URL/binding plus the concrete client class instantiated
   (`client_type`/`client_module`) as `selected_rpc_url` /
   `selected_transport_binding`. The harness fails if either is missing.

## Warnings, limitations, and disclosures

- Google ADK's own code emits `UserWarning: [EXPERIMENTAL]` for
  `to_a2a`, `A2aAgentExecutor`, `A2aAgentExecutorConfig`, and
  `AgentCardBuilder` — the ADK↔A2A integration itself is explicitly marked
  experimental by its maintainers, independent of anything in this spike.
- The `subprocess.Popen` launcher-PID-vs-true-PID divergence described
  above is a platform/tooling characteristic of this machine's Python
  venvs, not an ADK/A2A/MCP/LangGraph compatibility issue — verified via an
  isolated repro using a trivial subprocess unrelated to any spike code.
- `sse-starlette` had to be added as an explicit direct dependency of
  `services/istanbul-expert-b` (see above) — a real, disclosed gap in
  `a2a-sdk`'s own declared dependencies, not a silent workaround.
- `starlette` had to be added as an explicit direct test-only dependency of
  `services/istanbul-expert-b` and `services/travel-mcp` (see above) — a
  real, disclosed declaration gap found by audit, not a version change.
- The concrete A2A client class instantiated by `ClientFactory.create()`
  (`BaseClient`, `a2a.client.base_client`) is a generic type name that does
  not itself expose an introspectable "selected binding" attribute; the
  selected transport is recorded by explicitly requesting the binding(s)
  the discovered Agent Card advertises and matching the resulting interface
  back against the card, not by reading a directly-exposed client property.
- No skipped checks: every assertion in `phase0/verify.py` executed and
  passed on every run; nothing was mocked or stubbed in the live harness.
